# Lymphoma PET Follow-up Web MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Provide a runnable browser entry point for the existing research prototype's synthetic longitudinal PET/CT workflow.

**Architecture:** A local Python HTTP API imports existing domain modules without the PySide window. A React browser client renders PET/CT slices, edits a seed ROI, pairs lesions manually, and prepares a descriptive report. Server binds to loopback only.

**Tech Stack:** Python, Flask, Pillow, existing pydicom/numpy modules; React, Vite, TypeScript.

**Spec:** `docs/WEB_MVP.md`

## Global Constraints

- Keep the prototype identity in the bottom status bar; put the exact warning in exported reports. Do not add a top warning strip.
- Never calculate clinical response classifications.
- Invalid SUV evidence yields no formal SUV.
- Browser data is synthetic by default; local DICOM import stays under repository `data/`.

## Review Focus

- Different PET/CT slice counts: clamp each independently.
- Missing SUV: show an empty value with review state.
- ROI edits: keep original seed and source slice for audit.
- Pairing: only valid prior exams for the same pseudonymous patient.
- Refresh/reopen: saved lesions and report draft persist.
